# Проверка звонков FinChat

Клиент поддерживает личные аудио/видеозвонки и групповые звонки. Одновременно
на устройстве открыт один звонок. Состояние сохраняется при переходе между чатами.
Tinode отвечает за signaling, существующая LiveKit Room — за всё медиа.
Включение камеры не создаёт нового звонка или комнаты.

## Настройка API и сайта

1. Finchat должен объявлять `hi.ctrl.params.calls.provider = "livekit"`.
   Если поля нет, клиент показывает причину недоступности и не создаёт звонки.
2. Backend Finchat должен выдавать LiveKit JWT и отправлять уведомления через `me`.
   Нужно настроить LiveKit, его webhook и доступность медиа, включая TURN.
   Секреты LiveKit остаются на backend Finchat, веб-клиенту они не нужны.
3. Сайт должен открываться через HTTPS (для локальной разработки допустим localhost).
4. В окружении `server.mjs` задайте `LIVEKIT_URL=wss://call.finchat.club`, если хост
   отличается от значения по умолчанию. Этот параметр разрешает адрес в CSP;
   адрес подключения и JWT клиент получает из ответа Finchat.
5. Если перед Node стоит reverse proxy, его CSP и Permissions-Policy тоже должны
   разрешать камеру/микрофон своего origin и подключения к LiveKit.
   В `server.mjs` используется `camera=(self), microphone=(self), geolocation=()`.
6. После изменений пересоберите сайт и перезапустите сервер:
   `npm run build`, затем `npm start`. Vite preview не проверяет production-заголовки
   из `server.mjs`.

## Проверка двумя пользователями

Потребуются два отдельных тестовых аккаунта с существующим личным чатом.
Используйте разные профили браузера или разные устройства. Две вкладки одного
профиля синхронизируют авторизацию и не подходят для входа разными пользователями.
Для проверки звука используйте наушники.

1. Войти обоими аккаунтами, разрешить микрофон, открыть личный чат и нажать «Позвонить».
2. Во втором браузере убедиться, что входящий виден даже при открытом другом чате.
   Нажать «Ответить», проверить звук в обе стороны и счётчик разговора.
3. Выключить и включить микрофон, перейти в другой чат во время разговора.
4. Завершить звонок с каждой стороны; индикатор захвата микрофона должен исчезнуть.
5. Проверить отклонение, отмену исходящего, отсутствие ответа и запрет микрофона.
6. Провести разговор дольше минуты: срок первоначального JWT не должен его прерывать.
7. Проверить короткую потерю сети. После восстановления Finchat сверяет состояние,
   LiveKit восстанавливает звук средствами SDK. Если SDK окончательно отключился,
   клиент завершает участие и предлагает позвонить снова.

## Камера и окно звонка

- Начать видео сразу и включить/выключить камеру во время аудио: тот же callId/Room.
- Запретить камеру или подключиться без неё: аудио продолжает работать.
- Проверить local preview, remote video, переключение камер и аватар при camera off.
- Свернуть кнопкой, Escape или кликом по фону: окно справа сверху, чат доступен,
  микрофон и выход доступны в компактном окне.
- Развернуть окно; проверить «Большой экран» и кнопки под видео.
- Открыть «Звук и устройства»: сменить микрофон и устройство вывода в том же звонке.
  Mute должен сохраняться при смене микрофона. Новые remote tracks должны использовать
  выбранные наушники. Проверить подключение/отключение USB/Bluetooth-устройства и отказ
  в разрешении выбора. Если браузер не поддерживает setSinkId, вывод выбирается в ОС.
- Завершить звонок во время запроса разрешения камеры: захват должен остановиться
  даже при позднем разрешении. После повторного звонка старых tracks быть не должно.

## Группы

Для показа групповых действий сервер должен объявлять `calls.group: true` вместе
с `provider: livekit`. Лимит `calls.maxParticipants` и режим `calls.groupNotifications`
берутся из handshake; клиент не меняет политику рассылки backend.

При `notify` приглашение обновляет состояние группы без захвата экрана и рингтона.
В центре экрана появляется карточка с названием группы, кнопками «Подключиться»,
«Позже» и крестиком. Закрытие скрывает только карточку, без `leave`;
кнопка подключения в шапке группы сохраняется. Карточка не блокирует чат.
Короткий звуковой сигнал звучит один раз на callId. Если autoplay заблокирован,
в карточке доступна кнопка включения звука; доступ к аудиоконтексту разблокируется
при обычном взаимодействии с приложением.
Колокольчик в шапке списка чатов или кнопка в карточке явно запрашивает разрешение
Notification API. До согласия запроса разрешений и системных уведомлений нет.
После согласия новый invite также показывает системное уведомление; клик возвращает
к приглашению, без автоматического входа и доступа к микрофону. При закрытии карточки,
завершении звонка или logout соответствующие системные уведомления закрываются.
Это уведомления открытой вкладки, не Web Push: при закрытом сайте доставки нет.
Поддержка системных уведомлений и выбора аудиовыхода зависит от браузера/платформы.
Уведомления не дублируются для того же callId и исчезают при завершении или
подтверждённом отсутствии звонка. Подключение сверяет исходный callId через status.
При `ring`/`payload.ring: true` поддерживается обычное входящее приглашение.
Справа в шапке группы отображается кнопка начала или подключения, а в списке чатов — индикатор
известного активного звонка. Состояние открытой группы обновляется через `status`
при открытии, возврате фокуса и каждые 15 секунд; события применяются сразу.

Перед созданием или подключением клиент проверяет `status` с `seq: 0`.
К существующему звонку отправляется `join`, а не новый `pub`. Просроченный срок
первоначального приглашения не блокирует вход в уже принятый звонок. После выхода
можно сознательно войти повторно. Звонок другой сессии автоматически не перехватывается.

Состав и треки для сетки берутся из LiveKit, не из signaling participants.
Выключенная камера оставляет карточку с именем/инициалами. Зелёная рамка показывает
говорящего. В компактном режиме отображается говорящий либо первый участник.
Имена используют данные группы и доступное имя LiveKit; fallback — user ID.

Обычный «Выйти» отправляет `leave`. «Завершить для всех» показывается только по
`status.canEnd: true`, требует явного подтверждения и отправляет `end`.

Проверить минимум тремя разными аккаунтами:

1. Начало звонка и приглашение в режиме notify/ring согласно handshake.
2. Поздний вход третьего пользователя, в том числе после срока исходного invite.
3. Все видео/аудио в сетке, mute/camera off, вход и выход участников.
4. Выход одного участника не завершает разговор остальных; повторный вход возможен.
5. Завершение для всех доступно по серверному разрешению и закрывает все клиенты.
6. Открытие группы после пропущенного invite, reconnect, другая сессия пользователя.
7. Одновременное начало: не создавать дополнительные комнаты при ошибке backend.
8. Лимит участников и отказ в доступе; мобильная сетка, сворачивание и большой экран.

Автоматические проверки сигналинга и media state: `npm test`. Media-тесты используют
mock Room; они не заменяют настоящий микрофон, сетевой доступ к LiveKit/TURN
и разговор нескольких пользователей. Production-сборка: `npm run build`.
