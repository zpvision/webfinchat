# Прокрутка истории и нагрузка подписок

Дата: 2026-10-22. Базовая версия для сравнения: `27cc83d`.

## Найденные причины

- При изменении длины списка `Conversation` безусловно включал следование вниз.
  Отдельный таймер удерживал нижний край, а загрузка медиа могла запускать ещё один скролл.
- История сохраняла только scrollHeight/scrollTop до начала запроса. После движения
  пользователя или промежуточного пакета эти значения уже не описывали позицию чтения.
- Ответы пагинации и поиска цитаты не проверяли принадлежность текущему экземпляру чата.
- Два React-эффекта запускали подписки одновременно для всех тем. Каждый attach
  использовал собственный обработчик с JSON.parse для каждого входящего кадра.
- Форматтеры даты списка и времени сообщения создавались при каждом вызове.

## Изменения

- `src/messageScroll.js`: capture/restore по seq видимых сообщений и смещению относительно
  контейнера; запасные видимые якоря при удалении первого сообщения.
- `src/useMessageScroll.js`: единая политика следования, восстановление после commit,
  ResizeObserver для медиа и изменения размеров, очистка observer/rAF при уходе из чата.
- `src/App.jsx`: снимок непосредственно перед мутацией списка, в том числе для каждого
  потокового пакета; учёт прокрутки во время запроса; scope запроса и ключ экземпляра чата;
  защита истории, цитат, отправки и удаления от устаревших результатов; кнопка вниз;
  сохранение входящих сообщений при завершении начальной загрузки; общие Intl-форматтеры.
- `src/api/subscriptionQueue.js`: очередь на клиент с шестью фоновыми слотами,
  уступкой event loop, дедупликацией, отменой ещё не начатых задач и защитой React leases.
- `src/api/finchat.js`: очередь возобновляется существующим connect после opened;
  фоновые запросы ждут общий parsed packet stream. Закрытие сокета снимает ожидание;
  ответ и cleanup старого сокета не меняют подписки нового. Прямой attach остаётся прямым.
- Протокол Tinode, отдельные существующие запросы истории и media LiveKit не изменялись.

## Воспроизведение проверок

```text
npm test
npm run test:browser
npm run build
```

Для browser-теста нужен установленный Chrome/Chromium/Edge. Исполняемый файл можно
задать переменной `FINCHAT_TEST_BROWSER`; другой baseline — `FINCHAT_REVIEW_BASELINE`.
Тестовый Vite-сервер доступен только на 127.0.0.1. Он не публикует сайт и не обращается
к реальному FinChat. JSX App до/после и реальный realtime-клиент исполняются с контролируемым
транспортом. Экспорты компонентов добавляются только тестовым Vite-плагином.

Результаты последнего прогона сохраняются в `test-results/chat-review/results.json`.
Каталог исключён из Git. Для baseline нужен соответствующий commit в локальной истории.

## Проверенные сценарии

67 Node-тестов прошли, включая прежние проверки звонков и новые проверки:

- восемь страниц истории, изменение высот, запасной якорь после удаления;
- движение пользователя до получения ответа и сохранение текущей позиции;
- очередь из 100 тем, шесть слотов, дубли и ошибка отдельного чата;
- замена и отмена очереди, устаревший cleanup React-эффекта;
- foreground attach вне очереди и общая pendingSubscriptions-дедупликация;
- один JSON.parse на кадр при ожидающих подписках;
- настоящий жизненный цикл connect на тестовом WebSocket: восстановление неизменившихся
  тем, получение сообщения и входящего call invite;
- поздний ответ/cleanup старого сокета при новом attach той же темы.

В headless Chrome на реальном MessengerScreen/Conversation прошли:

1. Восемь последовательных подгрузок с движением во время каждого запроса.
2. Потоковый пакет истории до ответа каждой страницы; seq/offset сохраняются с допуском 2 px.
3. Входящее сообщение и настоящее отложенное событие загрузки изображения выше viewport.
4. Кнопка перехода вниз, следование входящим внизу и отправка сообщения из истории.
5. Переключение чата до завершения старого запроса: сообщения и положение нового чата сохраняются.
6. Reconnect с тем же списком тем; обновление непрочитанного счётчика и входящий экран звонка.
7. Отсутствие необработанных runtime-исключений.

Production-сборка прошла. Отдельный lint в package.json не настроен.

## Измерения до/после

Windows, Chrome 155.0.8059.85 headless, viewport 1280×900, CPU slowdown ×4.
100 одинаковых тестовых чатов, 120 мс до ответа подписки, 200 presence-кадров по 1 КБ.
Перед измерениями обе версии прогреты. По три измерения каждой версии, порядок чередуется.
Модули уже загружены: это измерение работы интерфейса от mount, не холодная загрузка сайта.
Время списка — до rAF, в котором все 100 строк уже находятся в DOM, а не метрика FCP.
Long Tasks — задачи ≥50 мс до окончания фиксированного потока кадров и подписок.

Это локальный синтетический сценарий с заметным разбросом. Он показывает ограничение

общее число pending может превышать 6 за счёт прямых foreground attach; ограничение
6 относится именно к фоновой очереди.

## Что остаётся проверить вручную

- Реальный сервер, большой рабочий аккаунт, сетевая задержка/потери и холодный запуск.
- Windows-оболочка на этом коде, её WebView и обработка ввода/масштабирования.
- Firefox, мобильный браузер, реальные видео/аудиовложения и нестандартные размеры медиа.
- Двусторонний LiveKit media-звонок при реальном сетевом восстановлении. Здесь проверен
  signaling и сохранены прежние mock Room-тесты; реальное медиа не подключалось.

Сайт не публиковался; backend/LiveKit server и секреты не изменялись.
