# Восстановление доступа

Перенесено из `handoff/finchat-access-recovery.zip` по `RECOVERY_HANDOFF.md`.
На экране входа есть кнопка-ссылка «Восстановить доступ». Модальное окно сохраняет
оформление архива: тёмный фон, фиолетово-бирюзовые акценты, три этапа,
два слова и восемь отдельных цифр. Tailwind/Radix/lucide не добавлялись:
используются React, отдельный CSS и нативный `<dialog>` с удержанием фокуса.

## Подключение и протокол

`src/api/accessRecovery.js` использует `createSocketUrl()` из существующего
`src/api/finchat.js`. Отдельных настроек recovery backend или ключа нет.
Адрес и публичный ключ берутся из `FINCHAT_HOST` / `FINCHAT_API_KEY` при сборке;
`VITE_FINCHAT_HOST` / `VITE_FINCHAT_API_KEY` имеют прежний приоритет. Если текущая
конфигурация использует same-origin `/finchat-channels`, восстановление использует
его же. Значений ключей в исходниках нет; `.env` не отслеживается Git.
Как и при обычном входе, выбранный браузерный ключ включается в сборку.
После изменения env нужна новая сборка. Для PROD задайте `FINCHAT_HOST=api.finchat.club`.

Каждая операция открывает свою **неавторизованную** WebSocket-сессию и сначала
завершает `hi` с версией `0.22`. Сессия сообщений/звонков не используется.

1. Телефон нормализуется в международный формат с `+`, без пробелов/скобок/дефисов.
2. SMS: `login.scheme=reset`, `login.secret=base64(wordcolor:tel:<телефон>)`.
   Ожидается `ctrl.code=301`. Это подтверждает приём запроса, а не доставку SMS.
3. Проверка: `acc.scheme=wordcolor`, `tmpscheme=code`,
   `tmpsecret=base64(<код>:tel:<телефон>)`, без `secret`, `user:new`, токена или входа.
4. При `ctrl.code=200` принимаются только непустые строки `word1`, `word2`
   и строка `digits` ровно из восьми цифр. Ведущие нули сохраняются.
5. Копируется `word1 + word2 + digits` без разделителей. Логин прежний,
   автоматического входа нет. Пользователь сохраняет данные и возвращается к входу.

## Ошибки и жизненный цикл

- Неверный/истёкший код (401/403) оставляет пользователя на этапе SMS.
- Повторный запрос разрешён не ранее 60 секунд; ответ 429 с `retry_after`
  может увеличить срок. Дедлайн хранится по номеру в памяти, переживает закрытие
  окна и не сокращается при последующих ответах. Смена номера не обходит его.
- После потери ответа на SMS действует минимальное ожидание: сервер мог уже
  отправить сообщение. Суточный лимит остаётся ответственностью backend.
- Команды автоматически не повторяются. При обрыве/тайм-ауте подтверждения
  показано, что результат неизвестен: пароль мог уже измениться.
- Нет localStorage/sessionStorage, URL-параметров, логов или автоматического
  заполнения входа с новым паролем. Закрытие размонтирует форму и очищает её данные.
- Во время запроса закрытие и повторная отправка блокируются. Клик по фону
  не закрывает окно; Escape работает после завершения запроса. При размонтировании
  запрос отменяется, сокет закрывается, таймеры и обработчики удаляются.
- При запрете clipboard данные остаются доступны для ручного сохранения.

## Проверки без SMS

```sh
npm test
npm run build
npm run test:browser:recovery
```

Unit-тесты `tests/access-recovery.test.mjs` проверяют протокол подставным WebSocket,
ошибки, отсутствие повторов, отмену/очистку и общую с обычным входом конфигурацию API.
Браузерный сценарий обслуживает фактическую production-сборку локально и подменяет
**все** WebSocket-соединения до запуска приложения; внешний HTTP/WebSocket-трафик
дополнительно блокируется. Настоящие SMS и смена реальных паролей не выполняются.

Проверяются клавиатура/Tab/Shift+Tab/Escape, возврат фокуса, клик по фону,
валидация, запрет закрытия во время запроса, отсутствие повторной команды,
неверный код, успешный ответ с `00123456`, копирование и его отказ, повторная
отправка, сохранение таймера после закрытия, серверные 120 секунд, потеря соединения,
повреждённый ответ и отсутствие записи данных в browser storage.
Размеры: desktop 1280×900 и mobile 390×844, 320×568, 320×380.
Скриншоты сохраняются в игнорируемый `test-results/recovery-*.png`.
Для другого Chromium задайте `FINCHAT_TEST_BROWSER`.

Остаётся проверить вручную на TEST по отдельному разрешению: реальную доставку SMS,
реальную смену пароля и вход с ним, серверный суточный лимит, Firefox/Safari,
системный clipboard и экранную клавиатуру на физическом телефоне.
Никакой деплой или изменение серверов эти команды не выполняют.
